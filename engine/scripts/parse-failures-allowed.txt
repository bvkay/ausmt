# scripts/verify.py FAILs a build whose build_report.json records a source_parse_failure that is not
# named here, so every line is a station the corpus publishes nothing for and a curator has decided
# to accept. Write one entry per line as `<survey slug>/<source file name>`, with the reason on a
# comment line above it. Adding a line is a curatorial decision and is reviewed like any other change
# to this repository; it is never a way past a red gate. Fixing the reader is, and that is what
# emptied this file: the one entry it carried was a reference latitude that repeated its sign
# character, which the pre-read conditioning now collapses on a temporary copy.
#
# The BUILD is unaffected: a corpus build still exits 0 on a refused file, because one malformed
# legacy file must not take the whole corpus down. This file governs the DEPLOY gate alone.
#
# A refused file is BOTH a parse failure and a dropped station: the build writes a row in each ledger,
# and stations-dropped-allowed.txt gates the other one independently. Giving up on a file therefore
# means writing it into both files, which is two deliberate acts for one lost station.
#
