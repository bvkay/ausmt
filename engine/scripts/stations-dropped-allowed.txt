# Stations the build DROPPED that this corpus has DELIBERATELY given up on.
#
# scripts/verify.py FAILs a build whose build_report.json records a stations_dropped row that is not
# named here, so every line is a station the corpus publishes nothing for and a curator has decided
# to accept. Write one entry per line as `<survey slug>/<source file name>`, with the station the
# build wrote and the reason on comment lines above it. Adding a line is a curatorial decision and is
# reviewed like any other change to this repository; it is never a way past a red gate.
#
# Entries are keyed on the FILE. The row's `station` is the id the build settled on BEFORE any
# station_ids override applies, so for a third-party release it is neither the file name nor the
# published id; it is recorded in the comment because a curator needs it to match a build log line to
# a row, and it is not what the gate matches on.
#
# The BUILD is unaffected: a corpus build still exits 0 when a gate refuses a station, because one
# station must not take a survey down. This file governs the DEPLOY gate alone. Its sibling,
# parse-failures-allowed.txt, gates the narrower ledger of files the READER refused; a refused file
# writes a row in both ledgers, and the two gates are independent, so giving up on one is two
# deliberate acts for one lost station.

# serve a transfer function under a sign convention it cannot establish, and the fix belongs to the
# custodian's export, not to AusMT. Stations CP1L05, CP2B13, CP2L01, CP2L02, CP2L08.

# KUTh Exploration, eastern Tasmania 2008 to 2010 (MRT open file, Phoenix SSMT cross-spectra EDIs):
# nine files refused by the rotation-frame gate. Each declares ROTSPEC=0 on every >SPECTRA block
# while its >HMEAS azimuths place the magnetic pair somewhere else (90, 180, 270 or 330 degrees),
# so the frame the spectra are stored in cannot be established from the file and the tensor is
# withheld rather than served in an unknown frame. The bytes stay in the packages, byte-identical
# to the lodgement; the packages' READMEs and survey.yaml record the nine. The build writes the
# Phoenix DATAID as the station (STL008-09A and so on) because the gate refuses the station before
# the station_ids override applies; the ids the packages would publish are the file stems.
# The remedy is a re-export in one coherent frame, which is curatorial work on the source files
# rather than a change to this gate.

# moradzadeh-mt-1996-97: four stations whose off-diagonal impedance phases both sit outside the
# quadrants the sign convention requires. These are a 2021 third-party WinGLink re-export of the
# thesis's Appendix II, and the export's rule was to apply the sensor projection the thesis's Table
# 3.2 implies and then negate the whole tensor. The appendix licenses a sign change of the
# off-diagonal elements alone and only at the sites Table 3.2 marks, so the negation is the export's
# own, and each refused station carries a further fault on top of it. BRU is the printed table
# negated bit for bit with no rotation involved, and the printed table passes this gate, so BRU's
# out-of-quadrant state is manufactured by the export rather than inherited from the appendix. EUR
# lost the magnetic half of the transform, so its served off-diagonals are minus the printed
# DIAGONAL elements and the responses served under EUR's name are another element pair entirely.
# EWD and SWD were transposed after a correct projection, which interchanges the two off-diagonal
# elements and with them the two modes; applied without the transposition both pass, and EWD
# carries four single-digit transcription slips besides. Correcting a custodian's numbers to make a
# gate pass is not AusMT's to do, so the four are served in the package and publish nothing until a
# corrected rendition exists.
# station BRU
moradzadeh-mt-1996-97/BRU.edi
# station EUR
moradzadeh-mt-1996-97/EUR.edi
# station EWD
moradzadeh-mt-1996-97/EWD.edi
# station SWD
