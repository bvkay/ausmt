1 · What is AusMT?

AusMT is a national discovery, provenance, and citation layer for Australian magnetotelluric (MT) transfer functions — the processed, instrument-independent response of the Earth at each site — so processed MT results can be found, trusted, reused, and credited. It is a discovery and provenance layer, not a raw-data archive.

2 · What can you do here?

Browse & download

Explore surveys on the map, screen station quality, and export data with citations.

Contribute a survey

Package and submit your EDIs with guided validation, entirely in your browser — your files never leave your machine until you submit. Local checks are advisory; a curator's repository review is authoritative.

API access

Machine-readable catalogue exports for GIS and scripts. MTCAT is AusMT's machine-readable catalogue format — one JSON file describing every survey, with GeoJSON available as an in-browser export for GIS. To script downloads, see Fetching data programmatically.

3 · What AusMT contains

  • Transfer functions
  • EDI products
  • MTH5 products, where supplied or generated through a documented pipeline
  • Survey and station metadata
  • Processing provenance — source file, SHA-256 checksum, extractor, pipeline and build version, git commit
  • Publications & DOIs, with ready-to-use citations and acknowledgements

Unknown values are shown as "not recorded" rather than guessed, so a reader can tell what is genuinely known about each product.

4 · What AusMT does not contain

  • Raw time-series
  • Geological interpretation
  • Redistribution of restricted data (still indexable metadata-only)

Where raw time-series exist, AusMT links to the archive that holds them (for example the NCI-AuScope MT collection) rather than hosting them itself. Openly licensed transfer functions may be served directly; otherwise AusMT lists the record and links out to the custodian's archive.
AusMT aims to make Australian MT holdings discoverable even where licensing or custodial arrangements prevent direct redistribution.

5 · Why AusMT exists

Australian MT data is scattered. The same scientific results are spread across university groups, government agencies, industry collaborations, supplementary files attached to papers, and ageing legacy archives, all in a mix of formats and conventions. That makes good data hard to find and easy to lose.

AusMT improves discoverability (one searchable map and catalogue), reproducibility (provenance travels with every product), reuse (consistent, standards-aligned metadata), and attribution (custodians and funders are credited, with DOIs where they exist).

7 · Fetching data programmatically

Everything the portal reads is a read-only static JSON file on this site: no key, no quota, no request signing. Every response carries Access-Control-Allow-Origin: * so a browser application can fetch it cross-origin, and every downloadable artifact is listed in the products manifest with a sha256 you can verify after downloading. Paths below are site-relative; the examples use https://ausmt.au.

Pattern A · whole-survey bundles

One request per survey, keyed by the survey slug (vulcan-2022 and the like; see the discovery note at the foot of this section for where to read one). Each published survey is packaged three ways:

  • /data/bundles/<slug>-edi.zip, every served station of that survey as EDI
  • /data/bundles/<slug>-xml.zip, the same stations as EMTF XML
  • /data/bundles/<slug>-tf.h5, the survey's transfer functions as MTH5
curl -O https://ausmt.au/data/bundles/vulcan-2022-edi.zip

Pattern B · manifest-driven per-station fetch

Fetch /data/products/manifest.json once, filter its files rows by format (edi or emtfxml) and by survey, then fetch /data/ joined to each row's url and check the bytes against that row's sha256. Go through the manifest rather than building paths yourself: a served filename is not derivable from the station id, so the manifest is the only correct way to locate one station's file. The manifest's other list, bundles, holds the Pattern A artifacts and the third format, mth5, which exists per survey rather than per station.

BASE=https://ausmt.au
curl -s "$BASE/data/products/manifest.json" \
  | jq -r '.files[] | select(.survey=="Vulcan 2022" and .format=="edi") | "\(.url) \(.sha256)"' \
  | while read -r url sha; do
      curl -s -O "$BASE/data/$url"
      echo "$sha  $(basename "$url")" | shasum -a 256 -c -
    done

The same loop in Python, standard library only:

import hashlib, json, urllib.request
BASE = "https://ausmt.au"
man = json.load(urllib.request.urlopen(f"{BASE}/data/products/manifest.json"))
for r in man["files"]:
    if r["survey"] != "Vulcan 2022" or r["format"] != "edi": continue
    body = urllib.request.urlopen(f"{BASE}/data/{r['url']}").read()
    assert hashlib.sha256(body).hexdigest() == r["sha256"], r["url"]
    open(r["url"].split("/")[-1], "wb").write(body)

An embargoed survey has no rows in the manifest at all: its bytes are withheld by construction, so there is nothing to request and no access error to handle, while its catalogue record stays public.

For survey-level discovery, start from mtcat.json, the MTCAT document that describes every survey in the catalogue in one file. Its survey records carry the slug under the key survey_id, which is the value both patterns above are keyed by; /data/surveys.json carries the same value under slug.

About this build
AusMT is a national MT research infrastructure. It indexes processed transfer functions and their provenance; it does not host raw time-series or make geological interpretations. The portal software is licensed under Apache-2.0; survey data remains licensed by its custodians (see Data policy).
